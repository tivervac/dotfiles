# Working agreements

## Never do the following unless I EXPLICITLY ask for it in the current request

Do not treat prior approval, being mid-task, or "it seems like the next step" as permission. If one of these would be a natural next step, stop and ask me first.

- **Commit** — no `git commit` (or any equivalent that creates a commit).
- **Push** — no `git push` (or any equivalent that publishes commits to a remote).
- **Reply on GitLab** — no comments, notes, review replies, or discussion messages on merge requests, issues, etc.
- **Any write/modification on GitLab** — no creating, editing, closing, merging, approving, labeling, or otherwise changing MRs, issues, branches, or any other GitLab state (via `glab`, the API, or the web).

Read-only actions (inspecting diffs, `glab ... view/list`, fetching MR/issue content, building/testing locally) are fine without asking.

## Writing style

Never use the words "load-bearing" or "seam". This applies everywhere: chat replies, code comments, commit messages, and documentation.
